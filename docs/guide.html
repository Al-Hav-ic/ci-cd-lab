01Що це за проєкт

ci-cd-lab — навчальний проєкт «Система продажу товарів у супермаркеті» (Гавриленко Олексій, Al-Hav-ic), який нарощується впродовж восьми лабораторних робіт: Git і CI/CD → проєктування (Use Case, UML) → PHP → ООП → Laravel API → бази даних → Blade-інтерфейс → Sanctum, Policies, Swagger.

  • Репозиторій: github.com/Al-Hav-ic/ci-cd-lab;
  • кожна лабораторна — окрема гілка feature/* і Pull Request (merge — після рев'ю одногрупника);
  • теорія до кожної лаби — у збірнику: theory-index.html / docs/theory/index.html.

03Швидкий старт

# 1. Клонувати та встановити залежності
git clone https://github.com/Al-Hav-ic/ci-cd-lab.git
cd ci-cd-lab
D:\PhPLabs\_tools\php\php.exe D:\PhPLabs\_tools\composer.phar install

# 2. Конфігурація оточення
copy .env.example .env
D:\PhPLabs\_tools\php\php.exe artisan key:generate

# 3. База даних (SQLite) з демо-даними
D:\PhPLabs\_tools\php\php.exe artisan migrate:fresh --seed

# 4. Запуск dev-сервера
D:\PhPLabs\_tools\php\php.exe artisan serve --host=127.0.0.1 --port=8000
  • БД для сервера — файл database/database.sqlite; тести жорстко використовують окрему in-memory SQLite (phpunit.xml), тому artisan test не чіпає демо-дані;
  • APP_DEBUG: true — з трейсами для відладки (стандарт .env.example); false — чисті JSON-помилки без трейсів (як у робочому .env, зручно для Swagger і скріншотів);
  • якщо порт 8000 зайнятий: Get-NetTCPConnection -LocalPort 8000 → Stop-Process -Id <PID> або запустити на іншому порту.

06REST API: /api/v1 (лаб. 8)

ЕндпоінтМетодДоступ
/api/v1/register, /api/v1/loginPOSTпублічні
/api/v1/products, /api/v1/products/{id}GETпублічні
/api/v1/categories, /discounts, /reviewsGETпублічні (read-only)
/api/v1/logout, /api/v1/userPOST, GETBearer-токен
/api/v1/products (створення)POSTBearer-токен → 201, без токена → 401
/api/v1/products/{id}PUT, DELETEBearer-токен + Policy: власник → 200, інший → 403
 
# отримати токен
curl -X POST http://127.0.0.1:8000/api/v1/login ^
  -H "Content-Type: application/json" ^
  -d "{\"email\":\"owner@lab.test\",\"password\":\"password123\"}"
# → {"user":{...},"token":"4|AbC..."}

# запит із токеном
curl http://127.0.0.1:8000/api/v1/products -H "Authorization: Bearer 4|AbC..." -H "Accept: application/json"

# демонстрація кодів: без токена → 401; DELETE чужого товару з токеном → 403

Завжди додавайте Accept: application/json — інакше помилки валідації повернуться редіректом, а не JSON.

Legacy API лаб. 5–6 (не змінюється)

Ендпоінти /products, /catalog, /orders, /carts, /reviews, /discounts працюють на сесіях без токенів. Записи (POST/PUT/DELETE) до /products та /catalog вимагають заголовок X-App-Client (будь-яке значення, напр. PartnerPortal) — інакше 403 з X-Security-Policy: Enforced.

07Swagger UI

Адреса: http://127.0.0.1:8000/api/documentation

  1. Розгорнути POST /api/v1/login → Try it out → вписати email/password → Execute → скопіювати token з відповіді;
  2. кнопка Authorize (зверху) → вставити токен у поле bearerAuth → Authorize → Close;
  3. далі будь-яка операція з Try it out → Execute виконує реальні запити: 201 для власних записів, 403 для чужих, 401 після Logout в Authorize.

Після змін в OpenAPI-атрибутах контролерів перегенерувати документацію: php artisan l5-swagger:generate.

09CI/CD цикл на GitHub

  1. Issue на GitHub (мітка enhancement) → додати на Kanban-дошку в колонку In Progress;
  2. гілка feature/* від гілки попередньої лабораторної (не від main) — так PR містить усі нові лаби;
  3. коміти за Conventional Commits (feat:, fix:, docs:…), закриття задачі — (Resolves #N);
  4. push → Pull Request → CI php-ci.yml: composer install → migrate → pint --test → artisan test;
  5. рев'ю одногрупника (branch protection: 1 approval, enforce_admins) → merge у main → Kanban-картка в Done.
