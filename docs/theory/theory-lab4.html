01Об'єктно-орієнтований підхід

ООП групує <strong>дані</strong> (властивості) і <strong>поведінку</strong> (методи) в класах. Об&#039;єкт — екземпляр класу. Переваги для проєкту <code>ci-cd-lab</code>:

    • повторне використання через наслідування й інтерфейси;
    • підстановка реалізацій (логер у конsole чи файл);
    • відповідність UML лаб. 2 (Product, користувач домену → Customer у коді, User на діаграмі → AbstractEntity).

02Клас, об'єкт, інкапсуляція

Інкапсуляція — приховування внутрішнього стану за модифікаторами доступу:
МодифікаторДоступ
publicскрізь
protectedклас і нащадки
privateлише цей клас
Constructor Property Promotion (PHP 8+): параметри конструктора одразу оголошують властивості — менше шаблонного коду в Product, User. Readonly (PHP 8.2+) — властивість задається один раз (наприклад, можна застосувати до сторін у геометричних задачах; у вар. 6 Triangle зберігає сторони через конструктор).

03Наслідування та abstract class

AbstractEntity у app/Models/AbstractEntity.php:
    • спільні поля id, createdAt і гетери;
    • abstract public function getDetails(): string — кожен нащадок (Product, Customer) зобов'язаний реалізувати.

Абстрактний клас <strong>не інстанціюють</strong> (<code>new AbstractEntity</code> — помилка).

04Інтерфейс vs абстрактний клас

ІнтерфейсАбстрактний клас
Стан (поля)не містить реалізації стануможе містити protected поля
Множинністьклас може implements багатолише одне extends
Призначенняконтракт «що робити»спільна реалізація «як частково»
ExportableInterface вимагає exportToJson(): string. Product implements інтерфейс і use трейт із реалізацією.

05Трейти

PHP не підтримує множинне наслідування класів. <strong>Trait</strong> (<code>JsonExportTrait</code>) додає методи в клас горизонтально.

get_object_vars($this) у трейті експортує властивості, видимі в класі-носії: private нащадка + protected батька. private поля батька в JSON не потраплять — у лаб. 4 id/createdAt зроблено protected. json_encode може повернути false → перевірка перед : string.

06Патерн Singleton

App\Core\Database:
    • private static ?self $instance;
    • private __construct() — заборона new Database();
    • public static function getInstance(): self;
    • private __clone(), __wakeup() з винятком — захист від другого екземпляра.
Призначення: один «пул» підключення (навчальна імітація). Мінуси: глобальний стан, складні тести — у production часто замінюють DI контейнером.

07Патерн Factory

EntityFactory::createEntity(string $type, array $data): AbstractEntity — match по типу (product, customer, синонім user), касти з масиву, default → InvalidArgumentException.

Клієнт (<code>public/lab4-demo.php</code>) не викликає <code>new Product(...)</code> напряму — додавання типу локалізоване в одному місці.

08Dependency Injection і SOLID

Dependency Injection: EntityService (клас у app/Services/EntityService.php) отримує LoggerInterface у конструкторі, а не створює ConsoleLogger всередині.

Принцип <strong>D (Dependency Inversion):</strong> залежність від абстракції, не від деталей. Реалізації: <code>ConsoleLogger</code>, <code>FileLogger</code> (<code>storage/logs/app.log</code>).

Методи: <code>calculateLineTotal(Product $product, ...)</code>, <code>registerProduct(Product $product)</code> — доменна логіка + логування.

Процедурні функції лаб. 3 перенесено в EntityFunctions.php, щоб не конфліктувати з класом EntityService.

8.1. SOLID у контексті лаб. 4 (коротко)

ПринципПриклад у репозиторії
S — Single ResponsibilityEntityService рахує суму; логер лише пише
O — Open/Closedновий тип у Factory через нову гілку match, без зміни клієнта
L — Liskov Substitutionзмінна AbstractEntity може тримати Product або Customer
I — Interface SegregationLoggerInterface — один метод log, без зайвих зобов'язань
D — Dependency Inversionсервіс залежить від LoggerInterface, не від FileLogger

Патерни <strong>не</strong> мета сама по собі: Singleton у <code>Database</code> — навчальна демонстрація; у production частіше реєструють PDO-сервіс у контейнері Laravel (лаб. 5+).

10PSR-4 і структура каталогів

app/
├── Core/          Database, EntityFactory
├── Interfaces/    ExportableInterface, LoggerInterface
├── Models/        AbstractEntity, Product, Customer (+ Laravel Auth User окремо)
├── Services/      EntityService, ConsoleLogger, FileLogger, EntityFunctions
├── Tasks/         Store, Product (склад), Person, Triangle, …
└── Traits/        JsonExportTrait

Ім&#039;я файлу = ім&#039;я класу. Autoload: <code>composer dump-autoload</code> після додавання класів.
