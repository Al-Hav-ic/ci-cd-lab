01Laravel у наявному репозиторії

Laravel — full-stack PHP-фреймворк з маршрутизацією, DI-контейнером, Eloquent ORM, Blade. У лаб. 5 скелет додають <strong>у корінь</strong> <code>ci-cd-lab</code>, зберігаючи:

    • .github/workflows/ (CI з лаб. 1, оновлений під php artisan test);
    • app/Models/AbstractEntity.php, Product.php, app/Core/*, app/Services/*, docs/;
    • tests/Unit/CalculatorTest.php.
Конфлікт імен: скелет містить app/Models/User.php для автентифікації. Доменний User з лаб. 4 перейменовують на Customer до копіювання Laravel.

Після merge: <code>composer require fakerphp/faker</code> (скелет перезаписує <code>composer.json</code>).

02Життєвий цикл HTTP-запиту

    • Клієнт → веб-сервер → public/index.php (front controller).
    • Bootstrap застосунку, завантаження routes/web.php.
    • Router підбирає маршрут за URI і HTTP-методом.
    • Middleware stack (глобальні + маршрутні).
    • Controller → відповідь (JSON, view).
    • Middleware на зворотному шляху (після $next).

Службові маршрути лаб. 5: <code>/health</code>, <code>/system-info</code>, Laravel <code>/up</code>.

03Artisan і генерація коду

Artisan — CLI Laravel: 
php artisan make:controller ProductController --resource
php artisan make:middleware CheckAppClient
php artisan route:list
php artisan test
php artisan key:generate
php artisan serve
--resource створює заготовку CRUD (index, store, show, …). Імена файлів і namespace мають відповідати PSR-4.

04Маршрутизація

Оголошення в <strong><code>routes/web.php</code></strong>:

МеханізмПризначення
Route::prefix('products')спільний префікс URL
->name('products.')імена products.index, products.store, …
->whereNumber('id')лише числовий {id}; /products/abc → 404 на рівні router
->middleware('product.access')аліас middleware на POST /products
Іменовані маршрути: route('products.show', ['id' => 1]) — стабільні посилання при зміні шляху. CartController@summary → GET /cart/summary (сервісний контролер, UC «Розрахувати суму» / кошик).

05Контролери

ProductController — ресурсний контролер сутності Product з UML:
    • index() — каталог (UC «Переглянути каталог»), опційний query manufacturer;
    • show($id) — картка товару, 200 / 404;
    • store() — створення (UC «Додати товар у каталог» / партнерський API), 201;
    • update / destroy / create / edit — заглушки 501 до лаб. 6–7.
In-memory mock: приватний масив $items у контролері. Через shared-nothing PHP новий запит = новий об'єкт контролера — POST не змінює список для наступного GET. У звіті це пояснюють; персистентність — Eloquent у лаб. 6. CartController — підсумок кошика (демо-дані, array_reduce).

06Request, валідація, JsonResponse

Замість <code>$_GET</code> / <code>$_POST</code>:

    • $request->query('manufacturer');
    • $request->validate([...]) — правила для name, price, stock_qty, manufacturer (відповідність атрибутам UML);
    • $request->hasHeader('X-App-Client') — у middleware.
response()->json([...], 201) — тип JsonResponse, заголовки (X-Security-Policy) додають у middleware після $next.

07Middleware і конвеєр

Патерн <strong>Chain of Responsibility:</strong> кожен middleware вирішує, передати запит далі чи повернути відповідь.

public function handle(Request $request, Closure $next): Response
{
    // до $next — вхід
    $response = $next($request);
    // після $next — вихід
    return $response;
}

Laravel 11/12: реєстрація аліаса в <strong><code>bootstrap/app.php</code></strong>:

$middleware->alias([
    'product.access' => CheckAppClient::class,
]);

Для тестів POST через Postman можуть тимчасово виключити CSRF для <code>products</code> (<code>validateCsrfTokens(except: [...])</code>). У <strong><code>php artisan test</code></strong> CSRF не заважає.

08CheckAppClient і безпека API

Бізнес-правило: створювати товари може лише партнерський клієнт із заголовком X-App-Client.
    • POST без заголовка → 403, JSON access_denied;
    • успішний прохід → контролер, відповідь із X-Security-Policy: Enforced.

Це спрощена заміна UC «авторизований партнер» до повноцінної OAuth/JWT. Middleware тримає правило <strong>окремо</strong> від <code>ProductController::store()</code> (Single Responsibility).

9.1. Структура Feature-тесту

$response = $this->withHeaders(['X-App-Client' => 'AutomatedTestRunner'])
    ->postJson('/products', $payload);

$response-&gt;assertStatus(201)
    -&gt;assertHeader(&#039;X-Security-Policy&#039;, &#039;Enforced&#039;)
    -&gt;assertJsonPath(&#039;data.name&#039;, &#039;...&#039;);</code></pre>

getJson / postJson автоматично встановлюють Accept: application/json. Тести не потребують запущеного artisan serve — Laravel bootstrap у TestCase імітує HTTP-шар у пам'яті.
