01PHP як мова веб-бекенду

PHP виконується на сервері; результат (HTML, JSON) надсилається клієнту. У лаб. 3 використовують вбудований сервер:

php -S localhost:8000

Кореневий <code>lab3-demo.php</code> / <code>public/lab3-demo.php</code> обробляють демо лаб. 3 (<code>/lab3-demo.php</code> при <code>php artisan serve</code>). Це спрощена модель Laravel, де точкою входу є <code>public/index.php</code>.

Файл починають з <code>&lt;?php</code> і <strong><code>declare(strict_types=1);</code></strong> — директива діє в межах файлу й уключає сувору перевірку типів аргументів і повернень.

02Масиви в PHP

PHP-масив — універсальна структура (ordered map):

ТипКлючіПриклад у лаб. 3
Індексний0, 1, 2, …п'ять категорій товарів
Асоціативнийрядкові іменаодин «об'єкт» Product

Корисні функції:

    • sort() / rsort() — сортування з переіндексацією;
    • foreach — обхід елементів;
    • count() — кількість елементів.

Для української абетки <code>sort(..., SORT_STRING)</code> може дати порядок кодових точок, а не словниковий; краще <strong><code>Collator</code></strong> з розширення <code>intl</code> (<code>uk_UA</code>).

Завдання 1 реалізують у app/Models/EntityArray.php: масиви + HTML-розмітка в одному файлі (навчальне спрощення; у Laravel View винесуть у Blade).

03Вивід у HTML і безпека

Будь-які дані з масиву, форми або БД перед виводом у HTML <strong>екранують</strong>:

htmlspecialchars($value, ENT_QUOTES, 'UTF-8')

Інакше можливий <strong>XSS</strong>: зловмисний рядок у назві товару виконається як скрипт у браузері.

Сторінка має <code>&lt;meta charset=&quot;UTF-8&quot;&gt;</code>, файли збережені в UTF-8 без BOM.

04Функції та strict_types

Користувацькі функції з типами аргументів і повернення:

function calculateLineTotal(float $price, int $quantity, float $discountPercent = 0.0): float

Без <code>strict_types=1</code> PHP <strong>приведе</strong> типи (рядок <code>&quot;1500&quot;</code> → число). З <code>strict_types=1</code> некоректний тип → <strong><code>TypeError</code></strong>.

Бізнес-перевірки (ціна &lt; 0, знижка &gt; 100 %) кидають <strong><code>Exception</code></strong> з зрозумілим повідомленням — це доменні помилки, не синтаксичні.

Функції з <code>app/Services/EntityFunctions.php</code> (процедурні функції лаб. 3) <strong>не автозавантажуються</strong> PSR-4 — потрібен <code>require_once</code> у <code>public/lab3-demo.php</code>.

05Замикання та array_filter

Closure (замикання) — анонімна функція, що може захоплювати змінні з оточення через use: 
array_filter($prices, function (float $price) use ($minThreshold): bool {
    return $price > $minThreshold;
});

Без <code>use</code> змінна <code>$minThreshold</code> всередині closure недоступна.

array_filter зберігає ключі вихідного масиву; для суцільного списку застосовують array_values().

06Винятки: try / catch / finally

try {
    $discounted = applyDiscount(1000.0, 150.0);
} catch (Exception $e) {
    // обробка помилки
} finally {
    // виконується завжди
}
finally корисний для логування або звільнення ресурсів незалежно від успіху. У звіті демонструють два виклики: з невалідною знижкою (150 %) і коректною (10 %).

07Composer і Faker

Composer — менеджер залежностей PHP. У composer.json:
    • require — runtime (наприклад fakerphp/faker);
    • autoload.psr-4 — простір імен App\ → app/.

Після <code>composer require fakerphp/faker</code> оновлюють <strong><code>composer.lock</code></strong> і комітять обидва файли — CI виконує <code>composer install</code> за lock-файлом.

Faker генерує тестові дані: 
$faker = Faker\Factory::create('uk_UA');
$faker->randomFloat(2, 150, 5000);
vendor/ у .gitignore; локально — composer install.
